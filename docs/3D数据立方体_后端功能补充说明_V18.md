# 备案分类、地址与立方体后端补充说明（V18）

依据前端提交的《3D数据立方体_后端接口需求(1).md》第 9—11 节和本轮聊天记录，供前端同学更新接口约定。本文记录**后端实际采用的确定规则**；原需求文档第 1—8 节中九层、24 成员等旧示例，以本文的 V18 差量为准。

## 1. 两级分类及接口代码

- `GET /api/v1/enterprise/filing/options` 路径和响应外形不变；`demo=false`，`natures` 返回 6 个一级性质、共 23 个二级性质，`industries` 返回 20 个一级行业、共 97 个二级行业，`addresses=[]`。行业来自 [国家统计局 GB/T 4754—2017](https://www.stats.gov.cn/xxgk/tjbz/gjtjbz/201710/t20171017_1758922.html)，性质来自 [国家统计局、市场监管总局 2023 年分类](https://www.stats.gov.cn/sj/tjbz/gjtjbz/202302/t20230213_1902786.html)。行业二级码始终是两位字符串，例如 `"01"`、`"35"`。
- 备案 `PUT /api/v1/enterprise/profile` 继续传 `natureParentCode`、`natureCode`、`industryParentCode`、`industryCode`，服务端校验正式字典的父子配对。`400/500/900` 在一级和二级使用相同的**对外**官方代码；内部字典父节点使用 `NATURE_GROUP_` 前缀避免主键冲突，客户端和备案记录始终只看 `400/500/900`。
- 六条旧演示字典和历史备案、报表快照保留用于读取追溯，不改写为猜测的正式码；新保存不接受演示性质、行业码。立方体无法确定正式一对一映射的旧码归入 `UNCLASSIFIED`，旧码仍保存在原备案及快照中。
- 聊天记录中的“取消行业大类模块”解释为**前端不单独出现第三个同级菜单**；立方体接口仍保留 `industryGroup → industry` 作为同一行业维度族的父子层级。前端显示「行业」并默认选 `industryGroup`，下钻到 `industry`。

## 2. 联系地址

- `PUT /api/v1/enterprise/profile` 新增可选 `contactAddress:string|null`。草稿允许空；`POST /api/v1/enterprise/filing/submit` 时 trim 后必填、最长 255 个 Java/JavaScript UTF-16 字符。缺失或超长为 400，错误键 `data.fieldErrors.contactAddress`。
- 新页面提交 `addressParentCode:null`、`addressCode:null`；这两个旧字段仅为历史读取保留，不再参与新地址校验。实际地址是纯文本，不改变账号所属地区和辖区权限。
- `GET /enterprise/profile`、企业/省级备案版本详情的 `profile.contactAddress` 返回保存的文本，旧版本没有文本时为 `null`，仍保留原 `addressParentCode/addressCode` 供历史展示。编辑旧草稿但未填写新地址时，不抹掉现存旧地址码。
- 备案 Excel 的“联系地址”列及报送期企业信息的 `addressName` 优先显示对应提交版本的文本地址；旧版本没有文本时使用旧地址字典名称。不把企业后来填写的新地址串到旧报送期快照。

### 备案请求中的关键字段示例

```json
{
  "natureParentCode":"100", "natureCode":"112",
  "industryParentCode":"C", "industryCode":"35",
  "contactAddress":"云南省昆明市五华区演示路 1 号",
  "addressParentCode":null, "addressCode":null
}
```

其余个人资料字段仍按原 `PUT /enterprise/profile` 契约提交。上例只是相关字段片段。

## 3. 立方体接口差量

- `GET /api/v1/province/analysis/cube/metadata`、`POST /query`、`POST /cell-detail` 路径与权限不变。`members` 现在有 **10 层**：`province,city,county,industryGroup,industry,natureGroup,nature,year,quarter,month`。`natureGroup → nature` 新增一级/二级性质关系，`industryGroup → industry` 与备案同源。
- `maxAxisMembers=40`、`maxCells=1800`。元数据含完整正式分类和必要的 `UNCLASSIFIED` 历史归类。`industryGroup` 轴在有样本且未加行业筛选时返回全部 20 个一级行业；有旧未分类样本时还会显示 `UNCLASSIFIED`。没有样本的组合仍不生成 `cell`。
- 查询和详情接受 `natureGroup` 轴及筛选；父层与子层属于同一个维度族，不能同时选作不同轴。`nature` 成员的 `parentId` 是一级性质的对外官方代码。二级行业 `industry` 的 `parentId` 是 A—T 门类代码。制造业有 31 个二级成员，可完整下钻。
- 详情无样本时返回 10 个空成员数组、6 个 `null` 指标。错误码沿用原契约；超限提示更新为“每轴最多 40 个成员，组合数不超过 1800”。

## 4. 市级调查期字典

新增 `GET /api/v1/city/reports/periods`，无查询参数，Bearer 登录并要求 `CITY.REPORT.READ`。返回 `{code:"OK",message:"成功",data:{items:[...],total:N},traceId:"..."}`。`items` 使用原 `SurveyPeriod` 字段 `code,label,startAt,endExclusiveAt,openAt,closeAt,currentVersion,windowStatus,demo,legacy`，按 `startAt` 从新到旧；旧演示期可能有空的 `openAt/closeAt`。不按报表状态截断期次，不分页。企业 `GET /enterprise/periods` 与原市级报表列表 `periodCode` 筛选不变。

## 5. 数据库与上线

Flyway `V18__filing_classification_address_city_periods.sql` 为 `enterprise_filing`、`filing_version` 各增可空 `contact_address VARCHAR(255)`，让提交版本旧地址码可空；补充正式行业 20+97、性质 6+23 条字典；加市级期次只读路由权限。保留全部旧演示字典、备案、报表、账号和快照，不批量臆造街道地址。本轮无需改立方体事实表或重建数仓。

上述改动可与现有服务器测试数据共存，**不以清空业务库为上线条件**。前端和测试同学若需重新准备样本，应先给出具体保留范围和样本方案，再定向清理；省、市级正式账号、地区字典、正式分类和迁移记录不可清除。
