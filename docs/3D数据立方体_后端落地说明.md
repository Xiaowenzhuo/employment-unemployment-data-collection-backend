# 3D 数据立方体及配套接口后端落地说明

依据 `3D数据立方体_后端接口需求.md` 实现，供前端联调使用。路径与请求字段按原需求文件调用；本说明补足其中由后端确定的规则。

## 立方体

- `GET /api/v1/province/analysis/cube/metadata`、`POST /query`、`POST /cell-detail` 均要求省级账号及 `PROVINCE.ANALYSIS.READ`。省域只从登录令牌推断。
- 使用数仓中省审通过、未作废的真实报表事实，每家企业每个实际调查期仅一行，人数取当前有效修订值。查询时先同步数仓，因此修订和作废会反映到新结果。
- 地区使用企业报表事实关联的市级组织与企业地区码。企业只填到市时，县级用该市的 `城市码:UNCLASSIFIED` 表示“未细分区县”。性质和行业使用提交时备案版本优先、当前备案回退后的数仓分类；仍缺失时归入 `UNCLASSIFIED`。
- 月份按调查期 `start_at` 转为北京时间判定。同一自然月若存在多个实际调查期，每期作为一次岗位观测累加；`periodCount` 是覆盖的不同自然月数。企业数始终按组织 ID 去重。比例由当前单元格人数重新计算。
- 筛选同层 OR、跨层 AND。无样本组合不返回 cell；合法但无样本详情的九层成员为空且六项指标为 `null`。单轴最多 24 个有样本成员，轴组合最多 1800，超限返回 422 `CUBE_LIMIT_EXCEEDED`，不截断。
- 新接口成功响应 `code=OK`、`message=成功`。现有旧接口的成功消息保持原样。

## 账号筛选

原有 `/province/admin/organizations` 新增 `parentOrgId` 直属父组织筛选；`/province/admin/users` 新增 `cityOrgId`，仅接受本省直属市组织，并筛选该市下企业组织账号。`orgId` 仍精确匹配，多个条件取交集，跨省或非市 `cityOrgId` 返回 404。均沿用现有 `PROVINCE.USER.READ`。

## 定向催报

- `POST /province/notices/report-reminders/preview` 和 `POST /province/notices/report-reminders` 要求 `PROVINCE.NOTICE.CREATE`。应报范围沿用现有调查期资格判断；有未作废真实提交的企业不催报，草稿、缺报、仅代填的企业可进入范围。
- 预览令牌有效 15 分钟，绑定发送人、省份、期次、范围和组织 ID 快照。发送前重新计算；名单改变、过期或无收件人返回 409。相同令牌及规范化正文在有效期内重试返回原通知 ID；更换正文返回 409。
- 定向通知的收件组织持久化。省级可管理；被选中的市组织或企业组织可见，市级收件不自动扩散至企业。未命中组织请求详情返回 404。普通省市公告的可见范围不变。标题和正文沿用 50/2000 Unicode 码点限制。

## 数据库

Flyway `V17__cube_reminders.sql` 增加通知定向标记、收件组织表、催报预览表及 5 条新接口权限路由。未增加立方体聚合表或缓存；地区、分类、期次及数仓事实使用既有表。部署前后需保留 V1—V16 校验和。

2026-11-16 已部署到服务器并完成 Flyway V17 迁移。部署前后保留原有 65 个账号、288 份企业报表。线上核验了立方体元数据、聚合、单元格详情、非法轴校验、直属市州筛选、按市筛选企业账号、催报预览及市级账号无权访问立方体。催报发送与收件可见性已在本地集成测试覆盖；线上预览的期次没有收件人，因此未向现有测试账号发送通知。
